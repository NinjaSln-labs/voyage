## 三、质量基调（为 M3~M6 确立标准）

### 1. 每个里程碑的验收必须包含
- **对抗性输入测试**：Unicode/变体/边界/语义欺骗——按本节防护矩阵逐项（新增面必须补矩阵行）
- **生产健壮性**：非法输入拒绝（非静默）、容量上限、深冻结、异常路径 fail-fast
- **事件协议**：载荷不可变（深冻结）、raw 保留原文（审计追溯）、发布-订阅闭环有测试
- **不变量↔代码映射表**：每个交付 README 附映射表（不变量→实现→测试）

### 2. 测试深度标准（契约基线之上）
```
happy × error × edge × adversarial × fault-tolerance 五类缺一不可
```

### 3. 代码规范红线
- 端口（模型/仓储/事件总线）返回值一律结构校验 fail-fast
- 时间/数值输入严格校验（NaN/Invalid Date/越界）
- 归一化匹配为服务端强制判定入口（任何分类不得用 raw 直接匹配）
- 事件载荷构造时深冻结；内部状态（摘要等）同样不可变

### 4. 审计节奏
- 每个里程碑交付后跑「完美收官审计」清单（本记录一二节为模板）
- 新攻击面出现 → 补入对抗矩阵 → 全量回归
