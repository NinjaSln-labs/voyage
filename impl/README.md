# 实施工作区（Implementation Workspace）

> 依据：`产品0-1计划.md` §2.5（技术选型与详细设计，阶段 0）
> 地位：**实施工作区**——产出设计交付物与决策记录；**不回写 `docs/` 基础文档集**（保持基础文档零技术栈绑定、无历史）。
> 输入种子（基础文档天然提供）：`产品说明书-终版` §5.2（能力 C1–C17）· §6.2（R1–R11）· §4.2（能力×角色矩阵）· §11（术语）；`需求说明书-终版` §2（RQ 需求化）· 附录 C（白名单）；`AI红蓝对抗报告.md`（Critical/Major 逐条固化不变量）。

## 目录

| 目录 | 内容 | 状态 |
|------|------|------|
| `m0-baseline/` | M0 基线：度量口径建档、评测集初建清单、DoD 勾选模板 | ✅ |
| `m0-t/` | M0-T 技术选型与 POC：评估框架、候选对比、POC 验收标准 | ✅ |
| `m0-d/` | M0-D 详细设计（DDD）：限界上下文/聚合不变量/领域事件/接口契约/数据对象/矩阵强制/安全时序 | ✅ |

## 原则

1. **零绑定**：基础文档保持纯能力描述；选型与设计的具体技术落地只在本工作区。
2. **可追溯**：每条设计条目可回溯到基础文档条目（C#/RQ/R#/矩阵）与红蓝报告不变量。
3. **验收**：M0-D 设计评审通过（不变量齐全、无孤儿规则、矩阵服务端强制）后方可进入 M1+ 实现与测试。
