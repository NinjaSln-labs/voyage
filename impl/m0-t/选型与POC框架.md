# M0-T 技术选型与 POC（评估框架）

> 依据：`产品0-1计划.md` §2.5.1
> 性质：**决策记录框架**——本文件定义评估流程与 POC 验收标准；具体候选方案对比与选中记录在 M0-T 执行时逐项填写（候选对比/选中理由/替换条件），**不回写基础文档**。
> 评估标准（顺序裁决）：**能力达标 ≥ 许可合规（强 copyleft 自用评估）≥ 成本（云 API 预算、硬件一次性）≥ 可维护性（配置驱动、可替换、契约测试覆盖）**。

## 1. 能力层评估矩阵（逐层填写）

| 层 | 能力要求（基础文档） | 候选方案 | 能力达标 | 许可合规 | 成本 | 可维护性 | 裁定 |
|----|---------------------|---------|---------|---------|------|---------|------|
| L1 感知 | 监控/日志采集（RQ-311/312；Agent <50MB） | 候选 A/B/C | ⬜ | ⬜ | ⬜ | ⬜ | 待评 |
| L2 决策 | 编排+模型路由（RQ-121/122/711/712） | 候选 A/B/C | ⬜ | ⬜ | ⬜ | ⬜ | 待评 |
| L3 知识 | 知识库+RAG/Embedding（RQ-211~213） | 候选 A/B/C | ⬜ | ⬜ | ⬜ | ⬜ | 待评 |
| L4 执行 | 无 Agent SSH 执行（RQ-411~418） | 候选 A/B/C | ⬜ | ⬜ | ⬜ | ⬜ | 待评 |
| L5 入口 | 统一网关+身份认证（RQ-611~614/811） | 候选 A/B/C | ⬜ | ⬜ | ⬜ | ⬜ | 待评 |
| 模型 | 云 API 路由/本地兜底/私有化（RQ-711~715） | 候选 A/B/C | ⬜ | ⬜ | ⬜ | ⬜ | 待评 |

**裁定规则**：先过能力达标（不达标直接出局）→ 许可合规（强 copyleft 仅自用评估，商业化前替换）→ 成本（云 API 预算 ¥50–80/月、¥100 告警；硬件一次性）→ 可维护性（配置驱动、契约测试覆盖）。

## 2. 关键能力 POC（每项验证后才进实现）

| POC | 验收标准（必须全部满足） | 依据 |
|-----|------------------------|------|
| P1 口语理解与术语翻译 | 口语集 ≥85%、术语集 ≥90%（公开集）；歧义意图触发确认流程 | RQ-113/112 |
| P2 受限执行链路（持有效许可） | Grant 只从审批单存储读取；聚合升级标志置位即挂起；审计先行 | RQ-416/624/633/831 |
| P3 设备/账号认证 | mTLS 无证拒绝；WebAuthn 注册双通道；审批 WebAuthn 唯一通道 | RQ-611/612/614 |
| P4 审计五元组链路 | 五元组落库 append-only+哈希链；审计失败操作回滚 | RQ-831 |
| P5 高危意图召回 | 高危集三集分别 100%（AND） | RQ-722 |

**POC 产出**：每项输出——验证结果、失败模式、与契约（m0-d）的偏差清单、替换条件。

## 3. 选型决策记录（执行时填写）

- 日期 / 评估人 / 每层候选对比表 / 选中理由（引用评估矩阵）/ 替换条件 / 批准（双人确认，防单点）
- **权限与审计**：选型决策记录属配置变更，走变更审计；模型/路由选型上线前必须过评测门禁（RQ-712）。

## 4. 契约测试要求（「组件是适配器」原则 #4）

- 每个适配器（监控/知识/执行/模型等）配契约测试：换组件 = 契约测试回归，不改领域。
- 契约以 m0-d 能力接口契约为准（见 `m0-d/04-能力接口契约.md`）。
