# ADR-006：矩阵「范围维度」设计（能力 × 角色 × 范围）

**状态**：已接受（设计已定，**实现延后**） · **日期**：2026-09-24 · **关联**：ADR-002（能力定义决定安全）、ADR-003（矩阵强制点）、ADR-004（矩阵行↔能力码映射）、RQ-415 / RQ-631 / RQ-632、p000045、t000035

## 背景

产品说明书 §4.2 矩阵的多处单元格带**范围限定词**，它们不是能力码、也非角色，而是「同能力、可见/可操作面收窄」的第三个维度：

| §4.2 单元格 | 范围限定词 | 语义 |
|---|---|---|
| 监控指标 / 服务状态查询 · 管理者 | 大盘 | 只可见聚合视图，不可见明细 |
| 日志查看 · 研发 | 自己负责的服务 | 目标须属于该用户的负责集合 |
| 日志查看 · 测试/产品 | 相关服务只读 | 目标须与相关服务集合相交 |
| 审计记录查询 · 研发 | 仅本人记录 | 结果集按操作者主体过滤 |

现状：能力模型只有 `capability × role`，**范围无服务端强制锚点**——带上限的单元格在实现层与「全量」单元格不可区分（例如「自己负责的服务」未校验归属、「大盘」未限制为聚合）。ADR-004 已把该缺口登记为 p000045，本轮经裁决**只出设计、不实现**（避免在无资产归属数据模型时改动判定契约）。

## 决策

1. **模型升维**：判定语境由 `(capability, role)` 升为 `(capability, role, scope)`。`scope` 为可选限定，缺省 `full`（＝该角色对该能力无范围收窄）。
2. **范围类型枚举**（与 §4.2 限定词一一对应）：
   - `full`：无收窄；
   - `aggregate`（大盘）：允许**聚合/汇总**读取，禁止明细返回；
   - `owned`（自己负责的服务）：目标须 ∈ 该主体的负责资产集合；
   - `related`（相关服务只读）：目标须 ∈ 相关资产集合，且仅读；
   - `self`（仅本人记录）：结果集按操作者主体过滤。
3. **强制点分层**（各范围只在能拿到所需数据的那一层强制；拿不到即 fail-closed 拒绝，不降级放行）：
   - `aggregate` → **判定层**：按 capability 与查询形态裁决（明细码如 `query_status`/`query_log` 不得以聚合口令触达）；
   - `owned` / `related` → **执行层**：目标资产归属校验（需资产-主体归属数据）；
   - `self` → **数据层**：结果集按主体过滤（需审计/记录携带主体）。
4. **本轮不改判定契约**：`Identity.hasCapability`、锚定前置校验（ADR-003）、`MATRIX_ROW_CAPABILITIES`（ADR-004）保持现状。范围维度在**数据模型就绪前不进入判定层**——否则会制造「有范围参数但没有归属数据」的假强制（比不实现更危险）。
5. **登记延后不变量 `INV-P4`**：范围限定词若进入判定，必须由其对应层（判定/执行/数据）实际强制；任一层缺失时，带范围的单元格须**拒绝**而非按 `full` 放行。

## 理由

- 范围是**正交维度**，不应塞进能力码（能力码是模型可匹配的动作对象，范围是可见性/归属约束）——否则能力码组合爆炸且模型无法可靠区分（ADR-004 已确立「能力码 = 模型可匹配粒度」的口径）。
- 强制点必须与数据可得性匹配：把 `owned` 放进判定层会因拿不到归属而只能臆测；把 `aggregate` 放到数据层又太晚（明细已出库）。
- 先设计后实现，是为了让 §4.2 的限定词有**明确归属与验收点**，并在数据模型（资产归属）就绪时一次落地，而非分多次造成契约漂移。

## 阶段 2 落地路径（t000035）

1. 建**资产归属数据模型**（资产 → 负责主体集合 / 相关集合），落 repo 层（零依赖 JSON，同 `repo-cloud-services` 风格）。
2. 判定层引入 `scope` 解析（`ROLE_CAPABILITIES` 由「能力数组」升为「能力→范围」映射，`full` 为默认），并在 ADR-003 强制点内叠加范围裁决。
3. 执行层加 `target ∈ owned/related` 校验（越界 → `REJECTED scope_violation`）。
4. 数据层加 `self` 过滤（审计/日志查询按主体收敛）。
5. 四类范围各补锚定测试 + 评测集样本；过评测门禁后合入。
6. 更新 §4.2 备注与 RQ-415/RQ-631 追溯；闭合 `INV-P4`。

## 影响与未覆盖

- **无代码变更**（本 ADR 仅设计）；`t000035` 跟踪实现。
- **未覆盖**：资产归属的外部数据来源与同步机制（依赖运维台账，另定）；`aggregate` 的查询形态识别是否需模型配合（可能引入新的模型字段，届时走 ADR-002 门禁）。
- 需求追溯：RQ-415（含只读面权限，见 §4.2）、RQ-631（矩阵唯一口径）、RQ-632（越权样本集）。
