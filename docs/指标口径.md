# 指标口径（Metrics Definition）

> 版本：v1 · 2026-08-18 · 依据：`产品说明书-终版.md` §7 · `需求说明书-终版.md` §6
> 用途：把"不可度量的目标"变成"可验收的度量"——定义北极星与反指标的**统计口径与数据来源**；口径变更须同步 `产品说明书-终版.md` §7 与本文档（防指标漂移）。
> 地位：本文档为**度量口径唯一权威**；计数冲突以本文档为准。

---

## 1. 北极星：非运维用户月自主完成查询/受限操作数

- **口径**：单次交互从「用户发起 → 系统受理 → 在无 SRE 人工介入下完成」计 1 次；受限操作类以「审批通过且执行成功」为完成标志。
- **用户范围**：研发 / 测试·产品 / 管理者；专业运维（SRE）不计入（SRE 另行计「分流受助次数」作参考指标）。
- **分类**：查询类（只读查询 / 知识问答 / 健康查看）与受限操作类（重启 / 清理 / 定时 / 扩容等经授权执行）。
- **计数点**：查询类取会话意图成功完成事件，操作类取作业执行成功事件——取自审计**计数事件流**（RQ-831：计数最小事件保序持久、独立于全量明细的溢出丢弃策略）。
- **统计周期**：自然月；附加率指标：月活跃非运维用户数、户均操作数、环比增长率。

## 2. 反指标 R1：AI 误执行导致的事故数 = 0

- **"事故"口径**：由 AI 生成或经平台执行后引发的服务不可用（含 P2 及以上）、数据损坏、越权/未授权操作，且需人工介入恢复或产生可见业务影响。
- **数据来源**：告警（≥P2）· 回滚记录 · 工单/值班记录 · 审计异常标记，交叉核对。
- **统计**：月度计数，目标 = 0；>0 即判该月达成失败，事故样本回填评测集（`AI评测策略.md`）。

## 3. 反指标 R2：审批绕过次数 = 0

- **口径**：审计事件中，高危操作执行缺少有效许可（Grant）或审批单（Approval）关联的记录条数。
- **数据来源**：审计事件（RQ-831）+ 高危面清单（`产品说明书-终版.md` §4.2 矩阵中需审批操作，对应 `需求说明书-终版.md` §6.3 S3）+ 审计完整性校验记录（哈希链校验日志）。
- **统计**：月度计数，目标 = 0。

## 4. 反指标 R3：高危操作未走审批比例 = 0

- **口径**：本月**未**走审批的高危操作数 / 高危操作总数。
- **数据来源**：同 R2；目标 = 0。

## 5. 关键阈值的属性（目标值 vs 实测基线）

| 指标 | 值 | 属性 | 基线建立方式 |
|------|----|------|-------------|
| 知识首问准确率 | >80%（开发）/>85%（生产） | 标准目标值 | 知识首问评测集（`AI评测策略.md` §1） |
| 口语理解准确率 | ≥85%（出处：需求说明书 §6.2 F2） | 标准目标值 | 口语理解评测集 |
| 术语翻译准确率 | ≥90%（出处：需求说明书 §6.2 F3） | 标准目标值 | 术语翻译评测集 |
| 回答可理解性 | ≥90% | 标准目标值 | 结果解释评测集 + 抽样观察 |
| 简单问答响应 | <5s（开发）/<10s（生产） | 目标值（实测校准） | 性能监控/压测 |
| 可用性 | 99.5% | 目标值 | uptime 监控 |
| 3 分钟上手 | — | 目标值 | 首次使用观察/走查 |

> 原则：阈值先作为**目标值声明**上线；每项在对应评测集/监控上建立**实测基线**后才视为"受验证"；基线建档于每次评测快照（`AI评测策略.md` §5）。

## 6. 口径变更流程

1. 口径变更必须**同步** `产品说明书-终版.md` §7 与本文档。
2. 变更前用上月数据回算新旧口径差异，评估后发布。
3. 以本文档为计数唯一权威。
