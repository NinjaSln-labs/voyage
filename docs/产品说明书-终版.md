## 1. 一句话定位

把**运维能力民主化**的 AI 运维平台：**听得懂大白话，指挥得了系统**。

**全球定位对位**：全球 Agentic AIOps 同类产品（云厂商 Copilot、企业级 Agent 运维平台等）均服务专业 on-call 工程师；行舟服务「**不敢碰运维的人**」——"the ops platform for everyone, not just on-call engineers"。

**护城河 = 口语化低门槛 × 零信任审批**（查询/诊断层正被云厂商免费化，差异化必须压在执行 + 信任审批）。

**能力底座**：查询/问答类能力（C5/C7 等）是获客与信任的**入口**，必须齐备；执行 + 信任审批为**留存与差异化护城河**——护城河不否定入口能力，二者互为支撑。

标语：潮平两岸阔，风正一帆悬 · *Smooth Sailing*

## 2. 愿景 · 使命 · 价值主张

- **使命（为什么存在）**：让每一个需要基础设施的人，都能用大白话安全地完成运维。
- **愿景终态（可度量）**：非运维用户每月自主完成的查询/受限操作数持续增长；AI 误执行事故数 = 0；审批绕过次数 = 0。
- **价值主张（分角色）**：

| 角色 | 价值主张 |
|------|---------|
| 专业运维（SRE） | 琐碎请求被平台分流，专注深度故障；高危操作有留痕双人审批 |
| 研发工程师 | 服务异常自查自愈不求人，3 分钟上手 |
| 测试/产品 | 环境可用性自主确认，测试不阻塞 |
| 管理者 | 随时看到健康/资源/成本大盘，及时知情 |

## 3. 目标 · 优先级 · 边界

### 3.1 核心目标与优先级（MoSCoW）

| # | 目标 | 优先级 |
|---|------|--------|
| 1 | 智能运维助手：理解自然语言、自动拆解任务并调度执行 | **M** |
| 2 | 降低使用门槛：非运维人员用大白话完成运维操作 | **M** |
| 3 | 统一操作入口：所有后台服务的统一 Web 入口 | S |
| 4 | 零信任安全体系：mTLS + WebAuthn + 操作审批，替代 VPN/堡垒机 | **M** |
| 5 | 知识驱动：Wiki RAG 智能检索与复用 | S |
| 6 | 多模型灵活接入：云端 API + 本地开源按场景路由，跟进 SOTA | S |
| 7 | 轻量免费：除模型 API 外全部开源免费组件 | C |
| 8 | 分阶段平滑交付：云 API 优先接入 → 配置化扩展与降级（本地兜底可选） | **M** |

### 3.2 目标冲突裁决原则

低门槛 × 零信任的张力按固定顺序裁决：**安全 > 体验 > 成本 > 便利**。审计与审批不可为任何体验优化绕过；本地兜底优先于体验流畅。

### 3.3 边界（非目标 / 反用户 / 商业模式 / 能力级不做）

- 非目标：不做通用 AI 问答；不依赖商业闭源软件；不要求变更现有网络架构；不要求普通用户掌握命令行。
- 反用户：不服务外部客户生产环境（仅自有/内部基础设施）；不服务纯通用问答用户；不服务 V1 未纳管的外部系统与云账号。
- 商业模式：内部工具，暂不商业化；除模型 API 按需付费外全部开源免费组件。
- 能力级不做（V1）：K8s 集群编排、APM 全链路追踪、多云/多账号资源编排、CI/CD 流水线、自研监控采集器、自研证书管理 UI 门户。

## 6. 信任与安全（领域核心）

### 6.1 零信任四层

| 层 | 机制 | 说明 |
|----|------|------|
| 设备级 | mTLS 双向认证 | 私有 CA 签发客户端证书，无证拒绝接入 |
| 账号级 | WebAuthn 通行密钥 | 生物识别/硬件密钥登录，防钓鱼 |
| 行为级 | 设备指纹 + 异常检测 | 异地登录、异常时间触发二次验证 |
| 操作级 | 高危操作二次审批 | 普通用户的高危操作必须经专业运维审批 |

### 6.2 关键业务规则

- R1 高危操作必须 ≥2 人审批，**操作者不可自批**。
- R2 审批有时限；超时**默认拒绝**并升级提醒。
- R3 审批决定幂等：一经批准/拒绝不可翻转。
- R4 非 read 类操作（write/egress/authorize）**必须持有效许可（Grant）**方可启动；许可仅以审批单存储为准，对话内容不构成许可；安全决策由能力定义的风险等级决定，不依赖模型分类输出。
- R5 许可有时效，过期自动失效；吊销须全网广播。
- R6 四层证据（设备/身份/行为/操作面）齐备才可准入；缺层即拒绝或分层动作。
- R7 审计五元组不可绕过，至少一次投递。
- R8 数据真实性：副能力只回真实观测/结果，AI 不编造指标，回答附出处。
- R9 非 read 类意图（write/egress/authorize）**必须先过信任预检**才能拆解为任务。
- R10 口语必须完成术语翻译后才能进入拆解；翻译表为准，模型仅辅助。
- R11 拒绝率过高时采用分层动作（提示/确认/审批）而非全拒。

### 6.3 AI 特有防线

幻觉误执行 → 执行前信任预检 + 白名单能力（清单见 `需求说明书-终版.md` 附录 C）+ 结果附出处可复核；Prompt 注入 → 意图解析与执行指令隔离 + 检索/日志内容数据-指令分层（数据不作为指令），仅白名单能力可执行；越权提示词 → 角色能力服务端强制校验 + 审计追溯；低置信度意图（<0.8）一律转确认/审批，不直接执行；**安全决策由能力定义的风险等级决定，不依赖模型分类输出**——模型只负责匹配文本到动作+能力，审批/拒绝由能力定义决定。

## 8. 产品原则（一票裁决依据，编号小者优先）

1. **安全优先于体验**——按「安全 > 体验 > 成本 > 便利」裁决。
2. **审计与审批不可绕过**——审批绕过 = 0 是红线。
3. **数据真实性**——AI 不编造指标；回答附出处可复核。
4. **组件是适配器**——业务真相在领域模型；换组件 = 契约测试回归。
5. **配置优于代码**——模型/组件/路由切换全走配置，<5 分钟生效。
6. **云 API 优先 · 本地兜底**——云 API 为默认优先，断连或敏感场景自动降级/切换本地模型；可用性优先于流畅。
7. **口语优先**——面向普通用户的输出通俗化；术语翻译以表为准。
8. **免费开源优先**——除模型 API 外不引入商业闭源依赖。
