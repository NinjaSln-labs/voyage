# 产品原则（Product Principles）

> 版本：v1 · 2026-08-18 · 依据：`产品说明书-终版.md` §8 + `需求说明书-终版.md`
> 用途：后续所有设计/实现争议的**一票裁决依据**；原则之间冲突时按编号顺序（编号小者优先）。

1. **安全优先于体验**——低门槛 × 零信任的张力按「安全 > 体验 > 成本 > 便利」裁决（产品说明书-终版 §3.2）。为什么：误执行一次事故的代价大于所有体验优化之和。
2. **审计与审批不可绕过**——反指标：审批绕过次数 = 0（产品说明书-终版 §7.1）。为什么：零信任是差异化护城河，绕过一次即失去全部信任。
3. **数据真实性**——AI 不编造指标与结果；副能力只回真实观测/执行结果，回答附数据出处可复核。为什么：假数据污染决策比没数据更糟。
4. **组件是适配器**——业务真相在领域模型；换组件 = 换适配器 = 契约测试回归，不改领域。为什么：对供应商中立的承诺（与「模型中立」同理）。
5. **配置优于代码**——模型/组件/路由切换全走配置，<5 分钟生效（先过评测门禁），不改代码。为什么：切换成本决定模型升级能否跟上 SOTA，门禁保证切换不降安全。
6. **云 API 优先 · 本地兜底**——云 API 为默认优先；断连或敏感场景自动降级/切换本地模型；可用性优先于体验流畅。为什么：99.5% uptime 承诺的最后一道防线，同时保敏感数据不出域。
7. **口语优先**——面向普通用户的输出通俗化（比喻/类比）；术语翻译以术语表为准（产品说明书-终版 §11）。为什么：门槛是产品灵魂，「听不懂」= 产品失败。
8. **免费开源优先**——除模型 API 按需付费外，不引入商业闭源依赖（开源组件含强 copyleft 许可时按自用合规处理，见需求说明书-终版 §7）。为什么：轻量免费是目标 7，商业化前须过许可评估。
