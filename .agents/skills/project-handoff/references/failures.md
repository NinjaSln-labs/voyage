# 失败出口（相位出错时读这一节）

- **每条报错自带出路**：报错末尾的「**修：**…」是**当场可执行**的下一步 ⇒ **先照它做**；本页是**成因与选择**的补充（同一类报错的来龙去脉、有几种修法时该选哪个）。**出路有五形**（命令／参数／用法／指令／无需动作）⇒ 只有**命令形**是「照着敲就能跑」；**指令形**是散文动作（可执行、不可复制）——它一样算数，别因为「不是命令」就当没出路。
- **`edit` 撞上**裁定件**（`dNNNNNN`）**：那条**在库里**，只是 `edit` 不改它 ⇒ 改判据走 `handoff decide <id> --status accepted|rejected|superseded`（原地改 `status` 一行，不换 id）；要另立一条走 `handoff add decision --title …`。

- **`check` 非零退出**：按输出行修——列出的即不满足的判据（槽缺失 / index 计数不一致 / id 冲突 / 日期违规 / `status` 值域 / `next` 无效或非 `open` / **文本槽死指针**）。修法只经 CLI：缺条目 `add`，多出条目 `rm`/`close`，**不手改文件**。**文本槽死指针**（`status`/`summary`/`exit` 提到一个既不在册也不在 `trash/`·`void` 的 `t`/`p`/`q`/`u` 型 id）修法：在文本里改掉那个引用，或把条目补回库里——**别去判据里加豁免**。若是**已作废**的 id 却被报，先确认它是否真在 `trash/`/`void`（在那儿就不会被报）；`c` 型不参与本判据是刻意的收窄（不是漏了）。**`c`/`d` 两型不在本判据范围内**（`d` 与 7 字符全 hex 的 commit 短 hash 形态不可区分），故这两型**不会**被这里报出——由 `view --id` 负责：查得到给记录，**已作废的明说「已作废」**（`rm` 落 `trash/` ＋ 记 `void`，与本闸「已作废 ≠ 不存在」同口径），真正查不到才 rc=2。「改号」另由本闸的 `decisions/<file>` frontmatter-id-等于-文件名判据兜。修完重跑，`OK` 为唯一通过判据。
- **`check` 报「X: status=blocked，但 blockedBy 指向的 Y 已不再生效」**（`blocked-stale` 维）：**这是事实矛盾，不是判据误报**——补位池谓词③说它「没被挡」（blocker 不再生效），入池谓词②说它「被挡」（`status≠open`），两头一夹它就**无人接手也无人看得见**。修法择一（报错里会原样印出可复制命令）：条件确已消失 → `edit X --status open`；改等另一件 → `edit X --blockedBy <还活着的 id>`；不值得等 → `close X --outcome "…"`。**别去判据里加豁免**。本维**只**判「指向已失效」，**不判**「`blocked` 却不写 `blockedBy`」——那只是没记指向，不是自相矛盾。
- **`add`/`edit`/`close`/`unconfirmed` 打印了「⚠ 含 shell 特殊字符」**：不是错误，是**提醒你核对**——若你用了双引号，这段内容可能已被 shell 展开（反引号＝命令替换、`$`＝变量）。**单引号安全**，该警告对单引号写法是噪声，可忽略；**要彻底避开就走 `--from-file`**——凡能落盘的自由文本字段都有这条入口（`close`/`unconfirmed` 都有，且参数面自证会当场拒任何「收长文本却没有不经 shell 入口」的子命令）。**真正要看的是紧随其后的「↩ 回读」块**——那是被吃掉的版本唯一会露出来的地方。
- **`check` 报「未经 CLI 记录的写入」/「疑似补手续」**：`writes.jsonl` 记的是**每次 CLI 写**后各文件的内容哈希与纳秒 mtime。手改文件不会留下记录 ⇒ 哈希对不上即报。修法：**别去改判据**，把那处手改经 CLI 重做一遍（`add`/`edit`/`set`），或直接从 `prev/` 快照恢复。若报的是「写之前发现被改动过」而内容哈希仍一致，那是**同字节覆写**的补手续痕迹——CLI 看不见那次手改的内容，但文件被动过的事实留下了。
- **`check` 报「本库还没有 **id 出处基线**」而库并不新（收过窗）**：≤5.72.0 的 `compact-writes` 折叠基线时漏掉出处维（`id_base` 基线并集、`ids` 分配记录并集）⇒ 唯一那条落基线的事件被折掉 ⇒ 基线永久失据；且 `_prov_live` 只看尾部窗口（保留事件带 `prov`）⇒ `handoff index` **不会**补基线（t000486，v5.72.1 已修：收窗并入两个并集、基线带 `prov` 键）。**已收过窗的库**：升级后跑一次 `handoff rebase --force`（显式结案口＝认账当前全部在册 id，认账单调只增）；若同时还有「分配记录失据」红项（点名具体 `p` 型 id），同一次 rebase 一并结案。别手改 `writes.jsonl`。
- **`check` 报出一堆「写入**之前**发现被改动过」而你确信没手改**：多半是**判据版本自身的缺陷**留下的历史误报（修判据不会消掉已写入的事件）。先**手工核对**那几个文件确实没被手改，再 `handoff rebase --force` 把基线对齐现实——它会逐条打印「已结案」清单，并把那些带旁证的历史事件**搬进侧档**（`.handoff/writes-rebased-<ts>.jsonl`，**不销毁**）⇒ 后悔了用 `handoff rebase --undo` 搬回（那些旁证会重新被报出来＝结案被撤销）。⚠ 同一次结案还把**当前全部在册 id 认账**（`id_base`）⇒「凭空出现的 id」维随之转绿，而**认账单调只增、`--undo` 不回退这一半**。核对在前。
- **`set` 被拒（空内容 / 骤降守卫）**：输出已说明是哪道守卫。确属要写空 → `--allow-empty`；确属大幅精简 → `--force`。**被拒时一个字节都没写、槽仍是原内容，不需要回退**——所以拒写信息里**不会**给「回退到 `prev/`」的建议（`prev/` 是**上一次成功写入**的版本，照做反而会把当前内容覆盖掉）。要回退用 `git` 或你自己的备份。**不确定就先 `set <slot> --file - --dry-run`**：逐条列出将丢失的行、不落盘（骤降判据在**极小内容**上不可靠——25 字符的槽删到 10 字符分不清「有意删一行」与「只喂了表头」，这类残余误用由 `--dry-run` 兜，而不是继续调阈值、再调就开始误伤正常删减）。
- **`check` 报「id 复用了已作废 id：X」**：X 同时落在 `void`（永不复用）与在册行里，两者矛盾。**先看报错后半句**——它在 `closed` 合法在册（多半是旧版 `rm` 在「live＋closed 同 id」的修复现场顺手记了 void）⇒ 走 `handoff unvoid X`（只摘作废标记，`closed` 那份照留）；条目本身也要从 `trash/` 搬回 live ⇒ 加 `--restore`，但**先确认 closed 没有同 id 行**，否则恢复出来就是双份，`check` 改报 id 重复（那条报错会再给你一次 `rm` 的修法）。
- **命令报「另一 handoff 进程占着本存储已超 Ns」**：锁是被占的，不是坏了。`pgrep -af handoff` 看有没有卡住的进程（真卡住的通常是自己在等自己：一条命令里嵌套调了 `handoff`）；没有就重跑。**别并行发多条写命令然后期待都生效**——默认 15s 的有界等待会串行化，超上限才报错，缩短 `HANDOFF_LOCK_WAIT_S` 只是把等待变成更早的报错。
- **`agents-block --check` 在认不出标记区的仓上 FAIL**：这不是错误而是**判定**——它会逐条列出「几行是标准条款的手写副本（收敛无损）、几行标准块里没有（install 后原样待在块外 `仓专属交接约定` 区）」。直接跑 `--install <仓根>` 即可，**不必先手工备份**（人写的行不删）。`handoff check` 的内置维（**只报不改**）：无 AGENTS.md 或无标记区＝不启用（未装块的仓不判红）；漂移／多份⇒**报红并给一条命令**（`handoff check --repair` 按唯一源重装；痕迹落 store 事件流，`handoff log` 可见）；残缺仍按本行 FAIL 并要求先解决（`--repair` 也不猜着修）。
- **`add` 报「参数面不符」**：你用的是旧 `add --slot <槽>` 并集形——按报错打印的新形重输（`add action|pitfall|command|decision --…`，每型只收本型字段）。
- **`add`/`edit` 报「status 非法」**：值域按型闭集（<!--fact:status-->action／command＝`blocked`｜`open`；pitfall＝`blocked`｜`fixed`｜`open`<!--/fact-->）；要关闭条目走 `close --outcome`（坑可走 `resolve <p-id> --outcome …`），不要把 `closed` 当状态写。注意 `pitfall` 的 `fixed` **只是自述、不是销账**——它**基本是自述**：别把「多数坑都 `open`」读成「多数坑都没修」。只有 next 指针判据读它（要求 next 指向 `open` 行）——那是守 next 有效性、不是销坑，**别为它加闸**；值域校验只验「在不在闭集里」，各槽计数与补位池都不看它。
- **`confirm` 不 PASS**：答案按 `handoff view` 行文本原样抄（去行首 `- `，含末尾 `(status)`）；若两次调用 `--seed` 不同，题已换，重取题再答。
- **无 `python3`**：询问用户安装；不可安装时**本技能不可用**（明确失败，不要手工改存储）——门禁缺失不得伪装成交接完成。

- **`check` 报「status=blocked，但**没记在等什么**」**（`blocked-owner` 维）：**这不是矛盾、是没记指向**——`blocked` 的行必须说清在等库内某条（`blockedBy`）还是在等所有者／用户／外部条件（`waitingFor`）。两者都没有 ⇒ 它不进补位池、无 owner、任何维都不报＝「无人接手但谁也看不见」。修法（报错里原样印出可复制命令）：等库内某条 ⇒ `edit X --blockedBy <还活着的 id>`；等所有者／用户／外部 ⇒ `edit X --waitingFor owner`／`--waitingFor user`／`--waitingFor external:<描述>`（三选一，**别把 `|` 一起粘**——那会被 shell 当管道）；条件已消失 ⇒ `edit X --status open`；不值得等 ⇒ `close X --outcome "…"`。**别去判据里加豁免**。
- **`check` 报「本仓**装过**交接块，现在块不见了」**（`block-installed` 维）：装块时库里会记一条 d 型「事实登记」。块被整段删掉后（本该由 `check --repair` 恢复）这条判据会点名。修法：`handoff check --repair` 或 `handoff agents-block --install <仓根>`；**本仓不再用交接** ⇒ `handoff rm <那条记录 id>`（落 trash ＋ 记 void）。
