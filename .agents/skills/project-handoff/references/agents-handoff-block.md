# AGENTS.md 交接块（标准源 · 由 project-handoff 持有）

> **这块是唯一源。** 每个项目在**自己**启用交接时（`init`）自动写入，块外内容不受影响；
> 若该仓已有 `## 交接` 整节但无标记区，**整节会被整理覆盖**（节外的其它章节不动）。
> 覆盖**不删人写的行**（5.1.0 起）：与本块逐行相同的是手写副本，收敛掉；不在本块里的
> 判成仓专属，原样搬进块外紧邻的 `<!-- handoff:repo:begin/end -->` 区，`--check` 不比它。
> 之后 `handoff check` 的 `agents-block` 维会自动做字节比对（无标记区＝不启用）：
> **漂移／多份只报不改**——门禁不改你的文件，要按本唯一源重装跑 `handoff check --repair`
> （痕迹落 store 事件流，`handoff log` 可见）；残缺仍红并要求先解决。
> 单独排查用 `agents-block --check`；显式 `--install` 仍可用于当场重装。
>
> **命令一律写 `handoff`**（PATH shim，指向技能自带 CLI；**`init` 不再自动装**——装它要跑
> `handoff install-shim`，幂等、不重复追加 PATH；无 shim 的环境回退＝
> `python3 <技能目录>/scripts/handoff.py`（Windows 用 `python`）。块里不写技能目录的相对路径
> ——各仓安装位置不同，写死必指错。**不要手改本文件里的条目**——改了不会同步到别的仓，
> 而 `--check` 会立刻报漂移。

## 另一档增强（不进块，按需手写）

本仓的判据有唯一定义点且可验证时，可另写：

- 判据的输入必须是落盘证据（命令输出、回执、快照），不是「谁记得上次怎么判的」。
- 判据迭代到线即停：硬失败判据总数与新增条件写在技能的 references 里，不在 AGENTS.md 复制。

## 写这块时的纪律（前三条来自 AGENTS-WRITING-GUIDE.md）

1. **不写运行状态**（条目数、发布量、日期）——会过期，且过期无痕迹。
2. **不写具体计数**（「三条命令」）——列举即可，计数一变就假。
3. **不写元话语**（「本节讲什么」）——agent 正读着这个文件，不需要被介绍。
4. **不写机制现状陈述**（「某文件记什么／不记什么」「某函数落在哪」）——块是**逐字节分发**到各仓的拷贝，
   而代码随版本走；`agents-block --check` 只比「块 vs 源」，**源自己过期它看不见**，所以这类句子坏了也没有闸会红。
   要指机制就指**命令本身**（让人当场跑），别替脚本描述它自己的实现。
