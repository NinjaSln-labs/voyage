# 常驻规则逐条说明（为什么）

> `SKILL.md` 只留**规则本身**（任一相位必须知道的），这里放**每条规则的来由与边界**。
> 需要时按编号来读；不需要就别读（本文不进每次入场的上下文）。
> 命令怎么用见 `references/cli.md`；报错怎么修见 `references/failures.md`。

## 一、角色

- **维度闭合**：<!--fact:slots-->9 槽（status／summary／scope／exit ＋ actions／pitfalls／commands／decisions ＋ unconfirmed）<!--/fact-->＋ 基础设施（index／next／closed／log）。槽外信息 → `unconfirmed`（未能确认），**不即兴开槽**——开槽＝改协议，而协议一改，全部判据与文档都得跟着改。（`confirm` 是**命令**不是槽——别把它当槽名找。）
- **只记不可推导项**：可读的用指针，读不到的才记——交接的意义＝**免重读仓库**。把能重读的推导结果抄进存储＝下次必漂。

### 状态由库里现算，散文不抄副本

`handoff view` 在**无时点**的行里给每个提到的条目标上真状态（〔已闭 日期〕／〔在册〕）⇒ 散文**不需要**、也不该自己抄一份。

- **写面不因状态拒写**：两个方向都不拦（判据不拿散文比库里活状态）。
- **括号型标记会被规范化掉**：无时点的行里、紧邻 id 的「（已闭）」这类标记，写入时被摘掉（回显里告诉你改了几处）；**带日期的行原样保留**——那是当时的说法，工具不裁决。
- **引用不改写**：写在反引号里的「`t000417（已闭）`」是**引用一个形状**（证据、举例），**不是断言一个事实** ⇒ 写入时原样保留；真状态仍由 `view` 标在**引用的外边**（`` `t000417（已闭）`〔已闭 2026-10-24〕 ``）⇒ 引用完整 ＋ 真相仍然给出。（写面行为契约见 `references/cli.md` §三。）
- **管状态的面只有一处**：三个**槽级散文**（`status`／`summary`／`exit`）——它们是给接班人看现况的。**归档行**（`closed/`）、**裁定正文**、**条目的 `detail`／`summary`** 都不在这张表里：前两者是**历史面**（载体自带日期，讲的是「当时」，工具不裁决）；后者是窄形态里唯一那两处引文 ⇒ 工具不去改它们。
- **代价（如实）**：机器不再替你裁决语义 ⇒「把活的说成死的」不再拦写 ⇒ 真状态靠**渲染标注**并排显示；读者不看标注仍可能被措辞误导。
- **不判语义 ≠ 不管**：散文里**点名不存在的 id** 仍由 `text-dangling` 维判红——那不是状态问题，是**指针坏了**。

### 派生数不抄进散文

`status`／`summary`／`exit` 里**不该出现现态计数**（槽计数由 `index` 每次写重建、`check` 的 `index` 维对账）——出现即 `derived-counts` 维判红，写入面 `set`／`append` 同形状当场拒。

- **唯一例外**：**没有例外**（现态计数只在 `view` 里现算；旧库残留的 counts 区由写路径幂等剥掉）。
- **带日期的历史快照放行**（那是当时事实，不是现态陈述）。
- **为什么拦形状不拦值**：值会漂且没人回头改；形状能钉死 ⇒ 这条判据只认形状。

### 输出有体量口径

「只报不拦」的提示**不是**可以铺开写的东西：它一旦铺开，真正的红项就被淹在后面，而提示本身又不拦任何东西。

- **口径**：提示类输出一律给**计数 ＋ 摘要**（点名最前面的几个，其余只给计数）⇒ 单行长度有界。
- **红项优先**：有红项时直接判红退出，提示不与红项同场 ⇒ 红项永不被提示淹掉。

### 事实只存一份，要插值，别手抄

**事实**（槽清单、id 形态、status 闭集、prio 闭集、写面上限、命令清单、waitingFor 值域…）**只存一份**：
原件在代码里的**事实表**（`FACT_VARIANTS` 是渲染形态、`DOC_FACTS` 是渲染区的值、`CHECK_DIMENSIONS` 是判据清单），随件文档与代码文案里**一律插值或指路**，不手抄第二份。

- **要插值，别手抄**：要陈述一个事实 ⇒ 引用它的**产生源**（插值）或指路（说明它在哪、怎么现算），不把值抄一遍。抄的第二份**必然漂**（源改了、抄的那份没人回头改）⇒ 纪律被违反时**静默**。
- **形态表不存派生值**：形态表（`FACT_VARIANTS`）是**登记处**——原件放这儿不算抄件；但登记处里若写着派生事实的**现值**（那种随结构变的），它自己就成了第二份抄件 ⇒ 产生源一改、表就漂。⇒ 表里只写**引用声明**（指向唯一源），现值在读时**实算**；表里出现派生源的现值 ⇒ 事实存在性闸当场红。
- **闸在哪、扫哪几面**：事实**存在性闸**（`fact_copy_violations`）扫**五个消费面**——随件文档散文、代码字符串、代码**注释**（AST 里没有注释节点 ⇒ 注释面用 `tokenize` 单独扫）、代码侧注册表单元、写面报错消息、读面红项。文档面**渲染区**的漂移由**文档面事实闸**（`doc_fact_violations`）管（漂移 vs 存在，二者分工）。
- **判据怎么算命中**（别自己猜）：形态分**数字类**（值＋单位 ⇒ 结构化比对，单位闭集在表内登记）与**符号类**（值域／形态串 ⇒ 整段逐字＋边界检查）⇒ 「单位不同／数不同／位数不同」都**不**命中。
- **例外**：**现行机制面里没有「历史」这档豁免**——「当时如此」的历史叙述若写在随件文档或代码文案里，仍是抄件（改它＝改证据）。**但历史面载体整体不在射程**：**历史面载体不在事实闸射程**——载体自带日期、讲的是「当时」的记录型载体（例：审计记录 `DESCRIPTION-AUDIT.md`）整份就是历史面 ⇒ 里面的事实陈述是**历史审计事实**、不是现态抄件 ⇒ 不判（登记在覆盖登记的「不管面·永久豁免」里；**永久豁免要写明理由**，空理由当场红）。⇒ 豁免表与实算**双向对账**：新增抄件没登记 ⇒ 红；豁免过期 ⇒ 红。

## 二、存储

- **键序固定**：`{"id","created","summary",[status,blockedBy,waitingFor],topic?,src?,detail?}`；归档行加 `closed`／`outcome`。
- **`id`**＝<!--fact:id--><t|p|d|u|c><6 位>（t→actions／p→pitfalls／d→decisions／u→unconfirmed／c→commands／q→closed）<!--/fact-->。**全局唯一、永不复用、脚本分配**——手选 id 迟早撞。
- **`decisions/<id>.md`**＝frontmatter（`id/created/status/domain/topic`）＋ ADR 正文。**标题在正文 H1**，frontmatter 不含 `title`（那是死键：writer 只把标题写成 H1，frontmatter 永不含它）。同型也装**事实登记**（如「本仓启用交接块」），用固定 topic「事实登记」区分。
- **`index`** 由脚本重建；**永不手写**（P2）。

## 三、不变量与机制面纪律

> **这三条是设计期纪律**（管的是「新增时该做什么」），与上面几条不变量同处一节，因为它们是**改这个包的人**要读的部分。机器判不了完整性（纪律全集没有机械可枚举的口径）⇒ 靠「新增时有人答」＋已登记者的锚点必现闸兜底。**理由不许空**（空理由＝无痕免检口）。

### 不变量

- **P1 不删**：只追加；`closed` 永不重写；移除仅在关闭序内原子完成。── 删掉的东西没法复查，交接件必须能回溯。
- **P2 可重建**：`index` 由脚本重建；**不生成、不落盘第二副本**。── 第二副本＝双源必漂（catalog 条款同病）。
- **P3 不静默**：每次运行输出「读到／写入／未能确认」；`confirm` 为**双向确认**。── 交接的价值在对方接得上，单向自说自话不算。
- **写路按行定位，不按 id 整表过滤**：一次只处置**一条**——`rm` 移走**那一条**、`close` 归档**那一条**、`edit` 改**那一条**、`unvoid --restore` 搬回**那一条** ⇒ 备份与恢复**按条数对称** ⇒ 用户没让删的那条不会被顺带处置，恢复时也不会多搬回来。
- **写入只经 CLI，且绕过必被抓到**：写事件台账记每个文件「**最后一次 CLI 写入时**」的内容哈希 ＋ 纳秒 mtime ⇒ 手改存储对不上即红；「同字节覆写」的补手续由 mtime 旁证抓（**内容哈希为主、mtime 只在哈希相同时作旁证**——mtime 可 `touch -d` 伪造，所以它只能当旁证）。
  - **封存（POSIX 上的内核级只读）是附加加固、不是这条保证的前提**：非 POSIX 平台上没有它，保护只剩对账这一道；`check` 会**显式提示**，不静默（别把绿灯读成「已封存」）。
  - **CLI 写到的载体一律进台账**：CLI 写过的每个文件（含裁定件载体 `decisions/<id>.md`）都要在写事件台账里留一条内容哈希记录 ⇒ 手改它就对不上 ⇒ 红。⇒ 载体面**不许有例外**（d 型曾被排除 ⇒ 导入来的裁定件改正文没人抓）；台账按**增量**记（只记变过的文件）⇒ 覆盖面补齐也不会把台账撑大。
  - **每个在册 id 都要有分配记录**：台账除文件哈希外，另记**每次分配**的条目 id ⇒ 在册的每个 id，要么出现在某条写事件的分配记录里，要么被**基线**认账（老库存量 id：基线＝**出处机制生效那一刻在册 id 的快照**，来历追不回来但可证明「那一刻就在册」）。
    ⇒ **为什么单独记「分配」**：文件哈希只对账**台账里有的文件** ⇒ 人手加的**新文件**不在射程；而「分配」这件事只有 CLI 做得出来、台账又只追加 ⇒ 这条记录**洗不掉**。
    ⇒ **老库怎么办**：基线**还没建立**的老库（没被新码写过）该维**不判**（存量 id 的分配记录追不回来，判了必误伤），但**不判 ≠ 闸缺席** ⇒ `check` 另出一条可执行红项（跑一次 CLI 写即自动认账；`handoff rebase --force` 是显式结案口）。
    ⇒ 出路：`handoff rebase --force`（认账：把当前 id 空间结案成基线——**认账单调只增、不可撤销**；`rebase --undo` 只回退旁证结案那半）｜`handoff rm <id>`（把那条移出去）。

### 机制面纪律（新增机制／契约时）

- **新纪律要同批登记**：新增机制或新增契约时，**先答**「它有没有一条要读者记住的纪律」——判「有」就同批登记进纪律清单（锚点抄进本文），判「没有」就不登记。── 这条纪律**自身有闸**（它不许被静默删掉），但它管的那件事（完整性判断）**没有闸**（纪律全集没有机械可枚举的口径），如实不冒充。
- **改契约必同批改命令参考**：命令的**行为、前提、出路**一旦改了（写路契约、恢复路径、报错出路），同批把**命令参考**（`references/cli.md`）改到与实现一致——**纪律登了不等于命令参考跟上了**（纪律必现闸只对账本文一份 ⇒ 命令参考不在它的射程里）。⇒ 配套做法：**改完契约跑一次「文档与实现对账」**（逐条命令核：行为、前提、出路与实现一致）。── 这条纪律**自身有闸**（不许被静默删掉），但它管的**同步**没有闸：命令参考这一面没有可机械枚举的全集 ⇒ 靠「改契约时同批改」＋多维实测的常设维度兜底。
- **子命令表只有一个源，别手抄**：加新子命令时**只改参数面**（`build_parser()`）⇒ 文档「命令全表」、出路判据、出路命令闸三处**自动跟上**。── 别把子命令名**另抄一份**到常量里（旧形抄过一份 ⇒ 抄件与实表漂移 ⇒ 文档漏项／出路闸误判「命令不存在」／反向漂移时放行**不存在的命令** ⇒ 用户照抄敲不通）⇒ 单一源闸会当场点名。── 闸判的是**形态**（不是某个变量名的某种写法）：**任何作用域**（模块级／函数体／类属性）的常量、**含**全表（超集也算——多出来那个命令在参数面里根本不存在）、写成 tuple／list／dict／拼接，都算副本。── 这条纪律**自身有闸**（副本复活 ⇒ 红），但它管的是「**新增时别手抄**」，完整性（有没有别的常量也该只有一个源）**机器判不了** ⇒ 如实不冒充。
- **每个机制都得声明有没有纪律**：新增机制／新增判据维／新增闸时，**同批**做两件事——① 该机制**值不值得**一条要读者记住的纪律？值得 ⇒ 登记它的**锚点**（读者能在文档里找到）＋ 它**守护哪些机制**（完整性闸的对账用）；不值得 ⇒ 登记「**无纪律＋理由**」。── **理由不许空**（空理由＝无痕免检口：没人知道它为什么可以不配纪律）。── 这条纪律**自身有闸**（完整性闸：每个机制都有声明 ⇒ 漏一条当场红），但它管的「值不值得」**是判断** ⇒ 机器只能对账**有没有声明**，判不了**声明得对不对** ⇒ 如实不冒充。

## 四、硬约束（逐条来由）

1. **不假设 git／语言／工具／布局；需用则先探测** —— 猜错一次就写错一件。
2. **未决语义唯一落点 `.handoff/`**（白名单硬契约）—— 其余处的待办文本是**候选**：写在那里的东西没有 owner、没有状态机、接班人看不见。
3. **维度闭合** —— 开槽＝改协议，判据与文档全要跟改。
4. **源登记表闭合** —— **只有 `scope` 登记的源被读**；未登记 → 非未决源（定义使然，不是漏扫）；登记必须**可解析**（路径存在／glob 有命中）——登记一个解析不到的源＝登记了一个假来源。
5. **迁移先于交接** —— 有旧模型时**告知用户并请求迁移**，同意后先走 `migrate`（它建存储）；别先建空存储、别在旧模型上直接交接（两边都有＝双源）。
6. **阻塞必须记「在等什么」** —— 阻塞有**三型**：被库内 id 挡（`blockedBy` 能表达）、**等所有者**、等用户答复／外部条件。后两型**没有库内 id 可指** ⇒ 那些条目永远没 blocker 可指，于是不入池、无 owner、任何维都不报＝「无人接手但谁也看不见」。**判据必须可满足**（补其一即可），否则只是噪声源。
7. **判据与修复分离** —— 门禁顺手改使用方的文件是**副作用**，而退出码不承载「我改过你的文件」⇒ CI 判绿、人只在 stderr 瞥见一句；且同一个技能里两张脸结论相反（显式 `--check` 报 FAIL，`check` 却修掉并报 OK）。**痕迹落既有事件流**，不新增退出码。
8. **标准交接块** —— 块是唯一源的**拷贝**，拷贝必然漂移；**不手工编辑块内条目**（升级改标准源再让各仓重装）。块内被手改 ⇒ 按唯一源重装，**人写的行不删**（搬到块外仓专属区）；标记区**残缺**（只有一端）⇒ 拒绝并报错（认不出块界就分不了「哪行是标准条款、哪行是你写的」）。装块即记一条 d 型**事实登记** ⇒ 块被整段删掉时 `check` 仍能判「本仓装过、现在不见了」。
9. **`init` 不再自动装全局 PATH shim** —— **项目级动作不越界改机器级状态**；要装显式跑 `handoff install-shim`（幂等，`--dir` 可选落位）。shim 是**解析式**的：安装来源在它自己的项目树内 ⇒ 用锚点（真源仓里跑源）；否则用 cwd 向上最近的 `.agents/skills/project-handoff`（**版本跟项目**）；再否则用户级标准位、安装来源；全无 ⇒ 报错退 127。
10. **崩溃最坏产生重复**（并发写有锁兜着，不交错）；**重复不会被动西掉** —— `check` 报 id 重复并给 CLI 修法（按 id 去重；`closed` 胜是 `import` 的容错，不是 `check` 的行为，别把两者混谈）。

## 五、反面清单（别这么干）

手改 `.handoff/` 条目（绕过 CLI → 改已有文件＝哈希对不上、**新增文件**里的条目＝没有分配记录，两道都会红；但别拿门禁当护栏）· 手填日期／自选 id · 重要度写回 `--summary "[高] …"` 前缀（写入即拒，只在 `--prio` 声明）· 未决写在 `.handoff/` 之外（→ 走 `unconfirmed`）· 手写第二份「视图／摘要」（→ 双源必漂）· 现态计数抄进散文（→ `derived-counts` 判红）· **`blocked` 不记「在等什么」**（→ 不入池、无 owner）· 手改判据清单生成块（→ 那是渲染物，改代码那一处再 `sync-dims`）· 手改文档里的**事实渲染区**（→ 同样是渲染物：槽清单／id 形态／status 闭集／prio 闭集／写面上限／命令清单都从代码派生，手改即漂）。

## 六、FAQ

**为什么不能直接编辑 `.handoff/` 里的文件？** 单一写入口是门禁的前提（日期／id／index 全由脚本管理，手改绕过校验且 `check` 兜不住）。**commands 槽常空？** 正常——S7 只收 AGENTS/README 里没有的非显然命令。
